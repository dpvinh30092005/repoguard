What repoguard Checks

Every time a merge request is opened or gets new commits, repoguard runs the checks below and reports them in three places: a status on the commit, one comment on the merge request that it keeps up to date, and the Merge Requests page here.

For issues, repoguard asks for missing details, adds labels, points out likely duplicates and flags stale or unassigned high-priority issues.

Try It in 5 Minutes

  1. Connect GitLabIn Settings, paste a token with the api scope and select Save Connection.
  2. Choose a Test ProjectIn Projects, select Start Checking. To try builds too, select Turn On Builds.
  3. Open a Merge Request With a Careless TitleCreate a branch, change a file and open a merge request called, for example, “update stuff”.
  4. Look at the ResultWithin about 30 seconds the merge request gets a repoguard comment saying the title does not follow the convention and the description is missing. The same appears under Merge Requests.
  5. Fix ItRename the merge request to feat: try repoguard and add a description. The comment and the result here update on their own.

Nothing Happening?

What You SeeWhat to Do
The header shows a GitLab connection errorThe token is wrong, expired or lacks the api scope. Create a new one and save it in Settings.
A merge request is open but not listedrepoguard only checks merge requests opened or updated after a project is added. Select Run Checks in Projects.
Conventions fails on every merge requestThe default rules expect titles like feat: add login and a linked issue. Change them for your team in .repoguard.yml on the default branch.
Build & Tests shows OffBuilds are off for the project. Turn them on in Projects if the project's own pipelines are disabled.
Build & Tests says it was not built automaticallyThe merge request comes from a fork, or its author cannot push to the project. Code from outside contributors does not run on shared machines.
