Guide

What repoguard does and how to try it.

What does repoguard do?

Whenever a merge request (MR) is opened or gets new commits, repoguard:

  • Checks MR conventions: a conventional title (e.g. feat: add login), a description and a linked issue.
  • Scans for secrets: passwords and tokens committed by mistake.
  • AI review (with an Anthropic key): inline comments on the changed code.
  • CI builds (if turned on): builds and tests the code in an isolated container or on Jenkins, for projects whose own pipelines are disabled.

For issues it asks for missing details, adds labels and flags likely duplicates.

Results appear as comments on the merge request and on the Overview page.

Try it in 5 minutes

  1. Connect GitLab: paste a token with the api scope and click “Save & test”.
  2. On Projects, pick a test project and click Start checking. To try CI builds too, click Turn on in the “CI builds” column.
  3. In GitLab, create a branch, change a file and open a merge request with any title, for example “update stuff”.
  4. Wait about 30 seconds (repoguard polls GitLab every 30 seconds), then look at the merge request: a 🛡️ repoguard comment reports the non-conventional title and the missing description. With CI builds on, a 🧪 repoguard ci comment with build and test results follows a few minutes later.
  5. Rename the MR to feat: try repoguard and add a description. The comment updates itself to ✅.

Already have open merge requests? Click Check now on the Projects page to check all of them.

Nothing happening?

SymptomWhat to do
The Overview page shows “Error” for GitLabThe token is wrong or lacks the api scope. Create a new one on the Connections page.
An MR is open but nothing shows upWait 30 seconds and reload, or click “Check now”. The “Recent activity” table shows any error.
There is a 🛡️ comment but no 🧪 oneCI builds are not turned on for the project, or the Overview page says “Image missing”: run the command shown there.
The 🧪 comment says “Not built automatically”The MR comes from a fork, or its author lacks Developer access. That is a safety rule, not a bug.
